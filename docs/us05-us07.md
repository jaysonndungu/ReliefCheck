# US05 and US07 local workflow

From the repo root, install the locked dependencies with `npm ci`. Use `npm.cmd` in PowerShell if script execution blocks `npm`.

```sh
npm run dataset:validate
npm run dataset:preprocess -- fixtures/synthetic/us07-extraction.json
npm run dataset:test
npm run dataset:typecheck
npm run build
```

## Update the draft dataset

The [draft manifest](../data/drafts/source-manifest.json) includes the [initial source inventory](us05-source-inventory.md) and the expanded coverage below. Edit its `sources` array and validate, or copy a single complete record into a separate JSON file, edit it, and run the commands below.

```sh
npm run dataset:upsert -- path/to/source.json
npm run dataset:validate
```

Upsert uses the exact stable ID. A new ID adds a record, and an existing ID replaces the entire record. Keep IDs stable across edits. Use `null` for unknown publisher, language, or publication date. Use `pending` with null review fields when a record needs review. For a reviewed record, enter the actual reviewer and timestamp and return it to pending if material evidence changes before re-review.

The two disaster keys are `valencia-dana` and `hurricane-melissa`. References use `{"kind":"web","url":"https://…"}` or `{"kind":"file","path":"private-source-reference.pdf"}`. A file reference identifies a private source. The CLI does not open it. Keep `background`, `campaign`, and `warning` distinct. These describe the source's purpose. A campaign candidate still needs separate evidence review for any current official-channel record.

New candidates start pending. This file remains a draft even if a row's metadata records a staff decision. Publishing, permission checks, and inclusion in an approved ingest manifest require the team's separate review flow.

## US06 handoff for Anson

From an API adapter under `apps/api/src/adapters/`, import `preprocessDocument` and the type `ExtractedDocument` from `../services/ingestion/preprocess.js`. The function takes the following arguments.

```ts
preprocessDocument(
  document: ExtractedDocument,
  source: Pick<SourceRecord, 'id' | 'disaster' | 'reference'>,
  options?: { targetChars?: number; maxChars?: number; overlapChars?: number },
)
```

`ExtractedDocument` follows the existing design in `ai.md`. Supply `sourceId`, the SHA-256 hex digest of the **raw snapshot** in `contentHash`, `title`, nullable `language` and `publicationDate`, ISO `retrievedAt`, and ordered `blocks: { text, page, heading }[]` with nullable page and heading. Give each PDF page or web section its own block. Include adapter warnings in `warnings: string[]`. Pass the validated source row as the second argument. For web snapshots, retain the original URL in the source reference. Keep the snapshot and any resolved URL with ingestion provenance.

Use `blocks`, `flags`, and `adapterWarnings` in the review preview. A true `needsReview` indicates a flagged extraction. Every source still requires staff approval. Severe flags return no chunks. The CLI prints the JSON result and exits with 2 for flagged input, 1 for invalid input, and 0 for unflagged input.

Chunks carry source and disaster IDs, title, language, publication date, original reference, raw content hash, block index, page, and heading. The `start` and `end` offsets are a half-open range in the **cleaned block** with the matching `blockIndex`, measured in UTF-16 code units. `textHash` hashes the passage and `cleanedHash` hashes the ordered cleaned blocks. The chunk `id` is a deterministic SHA-256 key for this source version and configuration. Persist it separately from a database UUID if the agreed schema uses UUID primary keys. Treat `preprocessingVersion` as the chunker version. Deduplicate within a version using the stable ID and retain the raw snapshot digest for source versioning. Repeated retrieval timestamps do not affect IDs.

The default target is 1,500 characters, maximum 2,400, and overlap up to 200. Paragraph and sentence breaks are preferred, with a word-boundary fallback. Chunks stay within their original page or section. A token longer than the configured maximum flags the extraction so a URL or other identifier can stay intact. Extraction, source approval, database writes, and publication belong to the surrounding ingestion flow.
